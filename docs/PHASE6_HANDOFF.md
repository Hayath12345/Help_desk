## Rules as built

- **Images.** Built from the repository root. `node:24.21.0-bookworm-slim` (patch pinned by the `NODE_VERSION` build argument), pnpm at the version of `packageManager`, `pnpm install --frozen-lockfile`. Runtime stages run as `node` (uid 1000) under tini with `NODE_ENV=production`, work with a read-only root file system (only `/tmp` is written), and have npm/npx/corepack removed. `api`/`worker` come from `pnpm deploy --prod` plus the generated Prisma client, then `prune-store.ts` cuts the Prisma CLI that `@prisma/client` drags in as an optional peer (a build step fails if it is still there). The API still runs through `tsx` (`node --import tsx src/server.ts`): there is no compile step in the repository. `migrate` holds the Prisma CLI, tsx, the migrations and the seed (its command is `prisma migrate deploy`; the production seed is `prisma db seed`).
- **Build arguments.** Only `NEXT_PUBLIC_API_URL` and `NEXT_PUBLIC_UPLOAD_ORIGIN` (web). `REQUIRE_RDS_CA` is a build switch. The web build fails unless the two public addresses are `https://` URLs of real hosts (`apps/web/docker-check-build-args.ts`); `REHEARSAL_BUILD=true`, passed only by `docker-compose.prod.yml`, lifts that for the local rehearsal image. The RDS CA files are not committed: download the global bundle and cut a single-certificate `rds-ca.pem` (guide section 4.3) into `deploy/certs/` before a production build.
- **Production configuration check** (`NODE_ENV=production`, which is also what an unset `NODE_ENV` means, and `DEPLOY_PROFILE=aws`, the default): `APP_URL` and `CORS_ORIGINS` https and not localhost; no loopback address (127.0.0.0/8, `0.0.0.0`, `[::1]` ...); `DATABASE_URL` with exactly one `sslmode` parameter, `verify-full` (only that value: `require`/`verify-ca` are refused because node-postgres will change their meaning; a repeated parameter is refused because node-postgres applies the last); `REDIS_URL` `rediss://`; both URLs free of `<...>` / `replace-me` placeholders and with percent-encoded credentials; `SOCKET_REDIS_ADAPTER=true` always; `TRUST_PROXY` set, at most 3 hops; S3 without endpoint, path-style or static keys; `EMAIL_PROVIDER=ses`, `SMS_PROVIDER=sns`, `TEAMS_PROVIDER=webhook`; the three region variables look like AWS regions. The web server adds: `AUTH_URL` required, https, not localhost. `DEPLOY_PROFILE=rehearsal` switches all of it off, logs a warning at start-up (api, worker and web), and exists only for the local rehearsal (and for `pnpm start` against the local services). On an AWS runtime (`ECS_CONTAINER_METADATA_URI_V4`, `ECS_CONTAINER_METADATA_URI` or `AWS_EXECUTION_ENV` set) api, worker and web refuse `DEPLOY_PROFILE=rehearsal` and any `NODE_ENV` other than `production`.
- **New variables:** `DEPLOY_PROFILE` (`aws`|`rehearsal`), `API_DOCS_ENABLED` (Swagger UI and OpenAPI document; blank = off in production, on elsewhere), `REDIS_KEY_PREFIX` (default `loons`; namespaces every key, queue and channel, so deployments can share a Redis; the rehearsal uses it for isolation), `WORKER_HEARTBEAT_FILE`. All in `.env.production.example`.
- **Health.** API `GET /health` (200/503, database + Redis, version; for monitoring and alarms, **not** for the load balancer) and `GET /health/live` (the ALB target-group check: a brief database or Redis outage must not make ECS replace every API task); web `GET /login`; worker: heartbeat file refreshed every 10 s while its consumers run and it is not stopping, checked by `node src/healthcheck-worker.ts` (fresh = at most 35 s). Dependency outages are not part of the worker check on purpose. ECS ignores an image's `HEALTHCHECK`: the guide has the task-definition commands.
- **Migrations on deploy.** One-off `migrate` task before the new services; idempotent; the old version keeps serving. Never `migrate dev`/`reset` in production.
- **Providers.** SES v2, SNS and S3 take their region from configuration (`SES_REGION`, `SNS_REGION`, `S3_REGION`) and credentials from the SDK's default chain; no static keys exist in the AWS path. The clients have connection/idle timeouts. Region and endpoint cannot be overridden by the test seam.
- **Graceful stop.** `api`/`worker` exit 0 after closing their connections; the web container drains 5 s and exits 0 (`NEXT_MANUAL_SIG_HANDLE=true` disables Next.js's own handler, which exits 143 at once).
- **Realtime behind a load balancer.** The browser socket client now sets `withCredentials: true` so the ALB's stickiness cookie is sent on the cross-origin long-polling requests (the API's CORS already answers `credentials: true`). More than one API task needs sticky sessions on the API target group and the Redis adapter.

## Gaps found while verifying (all fixed or documented)

1. **IAM needs `s3:ListBucket`.** The storage code relies on 404 for a missing object; S3 answers 403 without list permission. The Phase 2 IAM list omitted it (corrected in `PHASE2_HANDOFF.md` and the policy in `DEPLOYMENT.md`; a test pins the 404 -> null / 403 -> error behaviour).
2. **Prisma Migrate verifies TLS differently from node-postgres.** It ignores `sslrootcert`, accepts any certificate unless `sslaccept=strict`, takes the CA from `sslcert`, and **reads only the first certificate of the file** (found with `scripts/smoke-tls.sh`). One URL serves both clients (`sslmode=verify-full&sslrootcert=<whole bundle>&sslcert=<one certificate>&sslaccept=strict`): the primary documented path is a single-certificate `deploy/certs/rds-ca.pem`, the root of the instance's chain cut out of the regional bundle (procedure in guide section 4.3; `smoke-tls.sh` tests this URL shape with a private CA), with `accept_invalid_certs` for the one-off migrate task only as the last resort. **Which RDS certificate is the root of a given instance's chain could not be checked without RDS.**
3. **Prisma CLI inside the "production" API install** (optional peer of `@prisma/client`, 124 extra packages): removed by `prune-store.ts`, asserted in the build.
4. **Prisma downloaded the OpenSSL 1.1 engine** when the build stage had no OpenSSL; the Debian 12 runtime needs the 3.0 one. The build stage now installs OpenSSL first and the build asserts the right engine file exists.
5. **Next.js standalone exits with 143 on SIGTERM** and drops requests in flight: replaced by `docker-start.ts`.
6. **Socket.IO long-polling needs the stickiness cookie cross-origin**: `withCredentials`.
7. **No timeouts on the AWS SDK clients** (the SDK default is none): connection 5 s / idle 15 s (SES, SNS) and 120 s (S3).
8. **`sslmode=require` is about to change meaning in node-postgres** (it already prints a warning): production accepts only `verify-full`.
9. Source maps were shipped in the web image: removed.

## How to rehearse locally

```bash
docker compose up -d                 # postgres, redis, minio, mailpit
scripts/smoke-prod.sh --clean        # build everything from scratch, run it read-only, check it, tear it down
scripts/smoke-prod.sh --no-build     # reuse the images; scripts/smoke-prod.sh = build with the layer cache
scripts/smoke-tls.sh                 # verified TLS to a throw-away PostgreSQL and Redis (private CA)
```

The rehearsal creates `loons_rehearsal_<id>`, bucket `loons-rehearsal-<id>` and Redis prefix `rehearsal-<id>:`, uses host ports 3100/4100 (loopback), and removes all of it (it verifies that nothing is left). It refuses to delete anything that does not match those generated names. See `DEPLOYMENT.md` section 1 for what it proves.

## Known limitations

- Nothing was run against AWS: ECR/ECS/EKS, ALB (WebSockets, stickiness, idle timeout), RDS and ElastiCache TLS, S3 CORS/lifecycle on a real bucket, SES, SNS and Secrets Manager are documented, not tested. The IAM policy has never been evaluated by IAM.
- Region availability of SES and SNS SMS in `me-central-1` / `me-south-1`, and Qatar sender-ID rules, were not verified (the guide says how to point one service at another region).
- A build needs outbound HTTPS to: the base image registry (Docker Hub, or an ECR mirror), `deb.debian.org`, `registry.npmjs.org`, `binaries.prisma.sh` and, for the web image, `fonts.googleapis.com` / `fonts.gstatic.com` (`next/font/google`, IBM Plex Sans Arabic); the containers make none of these requests. The migrate image sets `CHECKPOINT_DISABLE=1` so Prisma's CLI does not call `checkpoint.prisma.io`.
- The base image is referenced by tag (`node:24.21.0-bookworm-slim`), not by digest; pinning the digest is a go-live hardening step in the guide (section 4.1).
- ECS Exec was not exercised. With a read-only root file system it needs writable `/var/lib/amazon` and `/var/log/amazon` and the `ssmmessages` permissions on the task role; the guide recommends a throw-away debug task instead (section 4.5).
- Redis: ElastiCache with cluster mode disabled is assumed (one primary endpoint); the client speaks RESP3 (`HELLO 3`) and falls back to RESP2 by itself. Neither was tried against ElastiCache.
- The API starts through tsx (a few seconds slower than compiled JavaScript). No compile step was added.
- `scanHook` is still the no-op (no virus scanning). `npm audit`/`pnpm audit`, `hadolint` and `trivy` were **not** run (they call external services or need installs that were not approved); ECR scan-on-push and a CI audit are in the go-live checklist.
- Fargate sizes in the guide are starting points from idle-memory measurements, not load tests.
- `AUTH_DEV_STAFF_LOGIN=true` is still silently ignored in production (the smoke asserts there is no staff password form); it is not a configuration error.
- Images are `linux/amd64` as built on the dev machine.

## Carry-overs after go-live

- Vendor the Plex Arabic font (a `localFont` file) so the web build needs no network. **Not decided by the owner**; the independent verifier recommends doing it (it removes a build-time dependency on Google and a possible build break), which is a small change.
- ClamAV / GuardDuty Malware Protection for S3 in `scanHook`.
- A pipeline (build, scan, push to ECR, migrate, deploy, smoke) and, if wanted, Terraform/CloudFormation or Kubernetes manifests (only the probe commands are documented).
- Compile the API to JavaScript (smaller image, faster start) or bundle it.
- Consider `transports: ['websocket']` for the browser socket client (no stickiness needed) if corporate proxies allow WebSockets for all clients; today polling is the fallback and stickiness is required beyond one API task.
- RDS Proxy if connection counts grow; a read replica for reports.
- Run `pnpm audit --prod` and an image scanner in CI; add `hadolint`.
- Verify the Prisma first-certificate behaviour and the choice of `rds-ca.pem` against a real RDS instance and simplify the migrate URL if possible.
- The remaining Phase 3/4/5 carry-overs (organisation-level P1 limit, sweeper for deliveries stuck in `QUEUED`, digest watermark, app-wide display time zone).
